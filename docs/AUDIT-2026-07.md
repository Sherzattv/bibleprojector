# Аудит Bible Projector v3 — июль 2026

Четыре независимых проверки: архитектура/код, производительность/данные,
UX/доступность, тесты. Сводка отсортирована по серьёзности.
Вердикт: фундамент правильный, но до «серьёзного продукта» нужно закрыть
блокеры ниже — прежде чем строить новые фичи.

## Критические (показ неверного контента / отказ в работе)

1. **Плейлист открывает не ту песню.** `setlist` ищет по `songNumber`, а
   номера в каталоге не уникальны: 3013 задвоенных номеров из 11 524 песен
   (№ 214 — это 6 разных песен). На проектор молча уходит чужая песня.
   → Хранить `song.id`.
2. **Офлайна нет вообще.** В v3 нет Service Worker: без интернета —
   белый экран. Для церковного зала это регресс против старой версии.
   → vite-plugin-pwa: app-shell precache + cache-first для данных
   с манифестом версий.
3. **Смена перевода может тихо подменить стих в эфире.** Позиция
   переносится по индексу слайда, а нумерация стихов в переводах
   расходится (31102/31163/31162 стихов; в РСТ задвоен Пс 12:6, в KYB
   33 пустых стиха). → Хранить `verse` в слайде, восстанавливать по VerseId.
4. **Space срабатывает с фокусом на селекторе перевода** (проверяются
   только INPUT/TEXTAREA): пробел = GO в эфир + стрелки двигают и селект,
   и превью одновременно. → Исключать SELECT и виджеты из глобальных хоткеев.
5. **Ctrl+Enter из поиска выводит первый fuzzy-результат сразу в эфир** —
   опечатка оператора = случайный стих на проекторе. → Мгновенный эфир
   только для точных ссылок; fuzzy — только в превью.

## Серьёзные

6. **Индексация поиска блокирует UI**: песни ~2 с на старте (6–10 с на
   слабом ноутбуке), перевод 1–4 с при первом полнотекстовом запросе;
   поиск на каждый символ без debounce (50–200 мс лаг ввода). Гонка в
   `$effect`+`setTimeout` (устаревшие результаты, «залипание» индексации,
   хиты старого перевода после переключения). → Web Worker для
   fetch+parse+index+search, debounce, отмена устаревших запросов,
   кэш сериализованного индекса в IndexedDB.
7. **Фоновая загрузка переводов без обработки ошибок**: нет `.catch` и
   `r.ok` — сбой сети = unhandled rejection и вечное «(загрузка…)» без
   ретрая.
8. **Ложный статус «Проектор · экран 2»** в шапке — окна проектора ещё
   не существует. Оператор думает, что подключён.
9. **Глубокие `$state`-прокси на 43 МБ данных** — вся индексация и поиск
   ходят через proxy-трапы (замедление в разы, лишняя память; 150 МБ heap
   с индексами, до 300 МБ при всех переводах). → `$state.raw`.
10. **Длинный стих обрезается на проекции без предупреждения**
    (`overflow-hidden`, фиксированный clamp-шрифт). → Autofit размера.
11. **Нет навигации стрелками по результатам поиска** + нет ARIA-модели
    combobox; blur-таймаут 150 мс теряет медленные клики.
12. **Потерянные функции старой версии, критичные к возврату**: заметка
    в эфир, редактирование текста слайда, открытие окна проектора,
    настройки проекции (шрифт/тема/размер), история показов.
13. **`show` намертво связан с глобальным `data`**, мутации сторов
    размазаны по компонентам — окно проектора, undo и персистентность
    потребуют слоя команд (openSong/openRef/setTranslation/go) — он же
    точка подключения BroadcastChannel.
14. **Конвертер данных хрупок и молчалив**: парсинг «первой строки с
    window.», нет валидации (66 книг, уникальность VerseId, пустые
    тексты). Грязные данные проходят в прод: дубль Пс 12:6 (РСТ) даёт два
    слайда «Стих 6», 33 пустых стиха KYB — пустые слайды.

## Средние

15. Контраст `--color-faint` ≈ 3.1:1 (ниже WCAG AA 4.5:1) на подписях
    10–11px. → Осветлить до ~#7a8290.
16. Мёртвые контролы: «Логотип» (и необработанный хоткей L), «+ Добавить»,
    заметки в плейлисте не открываются. → disabled или реализовать.
17. Тихие отказы: ненайденная глава/песня — никакой реакции UI.
18. Мёртвый legacy-код: используется малое ядро (canonical, parseQuery,
    splitSongSections), остальное — балласт; копии app/ и v3 разойдутся.
    → Обрезать, типизировать (`types.d.ts`), тест-страж идентичности копий.
19. Тесты: покрыт только удобный слой (~⅓ кода v3). Не покрыты: db
    (ошибки сети, demo-режим), Omnibox (гонки, Enter-приоритет),
    клавиатура App, конвертер. Нет CI (80 тестов запускаются руками двумя
    командами), версии vitest расходятся (2.x корень / 4.x v3).
20. Touch-таргеты 28px (планшетный пульт — реальный сценарий);
    активный слайд не скроллится в видимость при Space; Esc чистит эфир
    без подтверждения; нет aria-live статуса эфира.

## Порядок работ (принят)

- **Этап A — корректность**: пп. 1, 3, 4, 5, 7, 17 + валидация данных (14).
- **Этап B — производительность**: Web Worker поиска, `$state.raw`,
  debounce, кэш индексов (6, 9).
- **Этап C — офлайн и доставка**: Service Worker, манифест версий данных,
  деплой v3 (2).
- **Этап D — слой команд + окно проектора**: развязка show/data (13),
  BroadcastChannel, честный статус проектора (8), возврат функций (12).
- **Этап E — UX-полировка**: клавиатура в поиске (11), autofit (10),
  контрасты (15), touch (20).
- **Сквозное**: CI на каждом этапе, тесты на каждый пункт (19).
