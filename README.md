# Bible Projector v3

Bible Projector — локальная PWA-система для вывода библейских стихов, песен
и заметок на проектор. Пульт оператора и экран трансляции работают в
отдельных окнах, без аккаунта и серверной части.

Основная линия разработки: **3.0.0-preview.1** в каталоге [`v3/`](v3/).
Все новые функции, исправления и архитектурные решения делаются только для
v3.

Runtime v2 удалён из репозитория. Исходные базы перенесены в
`v3/data/source/`; production, CI и документация относятся только к v3.

## Что работает в v3

- единый поиск ссылок, текста Библии и песен;
- четыре перевода: RST, NRT, KTB и KYB;
- офлайн-каталог из 11 524 песен;
- Preview/Live, сетка слайдов и управление эфиром;
- отдельное окно проектора через BroadcastChannel;
- размещение окна на внешнем мониторе с безопасным fallback на popup;
- blackout, заметки, правки текста и настройки проекции;
- автоподбор размера длинного проекционного текста (autofit);
- навигация стрелками по результатам поиска с ARIA combobox-моделью;
- сохраняемые порядок служения и история эфира;
- импорт/экспорт порядка и миграция данных из v2;
- PWA, офлайн-кэш оболочки и версионированный кэш данных;
- desktop-интерфейс оператора с минимальным поддерживаемым окном `1280×720`;
- браузерные E2E-сценарии стихов, многосекционных песен, полного цикла
  порядка, восстановления состояния и отдельного окна проектора.

## Быстрый старт v3

Для приложения требуется desktop-версия Chromium. Для разработки также
нужны Node.js 22 и npm.

```bash
git clone https://github.com/Sherzattv/bibleprojector.git
cd bibleprojector/v3
npm ci
npm run data
npm run dev
```

Откройте адрес, который покажет Vite, обычно
`http://127.0.0.1:5173/`. Экран проектора открывается кнопкой в шапке или
по тому же адресу с хэшем `#display`.

`npm run data` создаёт в `v3/public/data/` JSON-базы из исходников в
`v3/data/source/`. Сгенерированные файлы не хранятся в Git.

Пульт оператора рассчитан на desktop-окно от `1280×720`. Планшеты и
телефоны не входят в поддерживаемые платформы. Узкая раскладка остаётся
аварийным fallback, но не является релизным требованием и не тестируется.

## Основное управление

| Действие | Клавиша |
| --- | --- |
| Перевести фокус в поиск | `Ctrl + K` / `Cmd + K` |
| Выбрать результат поиска | `↑` / `↓` |
| Открыть точную ссылку в Preview | `Enter` |
| Отправить точную ссылку сразу в Live | `Ctrl + Enter` / `Cmd + Enter` |
| Отправить Preview в Live | `Space` |
| Предыдущий или следующий слайд | `←` / `→` |
| Включить или выключить blackout | `B` |
| Очистить Live | `Esc` |
| Полноэкранный режим окна проектора | двойной клик по экрану |

`Ctrl/Cmd + Enter` не отправляет fuzzy-результаты в эфир: быстрый Live
разрешён только для точно распознанной ссылки.

## Проверка v3

Из каталога `v3/`:

```bash
npm run check
npm test
npx playwright install chromium
npm run test:e2e
npm audit --omit=dev
```

- `check` — строгая проверка Svelte и TypeScript;
- `test` — модульные тесты Vitest;
- `playwright install` — однократная установка Chromium для E2E;
- `test:e2e` — конвертация данных, production-сборка и браузерный тест;
- production-аудит на текущем lock-файле не содержит уязвимостей.

Из корня репозитория:

```bash
npm run build && npm run smoke
```

- `smoke` — дымовой тест раздачи: поднимает `wrangler dev` на уже собранном
  `dist/` и реальными запросами проверяет, что `/` отдаёт лендинг, `/app/` —
  приложение, данные приходят как `application/json`, а несуществующие пути
  получают 404.

CI проверяет Svelte/TypeScript, модульные тесты, полный production build
через Wrangler и дымовой тест раздачи. Браузерные E2E в CI не запускаются —
их прогоняют локально (`npm run test:e2e`) перед релизами.

`wrangler deploy --dry-run` сам по себе не заменяет `smoke`: он валидирует
конфиг и выходит, не обслуживая ни одного запроса, поэтому ошибки раздачи
(`html_handling`, `not_found_handling`) для него невидимы.

## Сборка и публикация

Из корня репозитория:

```bash
npm run build
```

Команда устанавливает зависимости v3 по lock-файлу, генерирует данные и
собирает публикуемый каталог `dist/`: лендинг из `site/` в корне и
приложение (сборка v3 с base `/app/`) в `dist/app/`.

```bash
npm run deploy
```

Wrangler запускает production-сборку и публикует `dist/` через Cloudflare
Workers Static Assets:

- [bibleprojector.kz](https://bibleprojector.kz/) — лендинг;
- [bibleprojector.kz/app/](https://bibleprojector.kz/app/) — приложение.

Для Git-деплоя Cloudflare Workers Builds должен использовать:

```text
Build command: npm run build
Deploy command: npx wrangler deploy
Root directory: /
```

Эти строки живут в дашборде Cloudflare, а не в репозитории: Workers Builds
не читает секцию `build` из `wrangler.jsonc` — она работает только при
локальном `npm run deploy`.

Путь `/next/` больше не используется.

### Раздача статики

Два параметра в [`wrangler.jsonc`](wrangler.jsonc) определяют, что вообще
откроется у пользователя. Оба уже ломали прод, поэтому менять их стоит
только вместе с прогоном `npm run smoke`:

- `html_handling: "force-trailing-slash"` — каталог отдаётся как
  `index.html`: `/` → `dist/index.html`, `/app/` → `dist/app/index.html`.
  При `"none"` путь `/app/` не совпадает ни с одним файлом и уходит в
  `not_found_handling`, то есть пользователь получает лендинг вместо
  приложения.
- `not_found_handling: "404-page"` — несуществующие пути получают честный
  404 и `dist/404.html`. SPA-фолбэк приложению не нужен (клиентского
  роутера нет, окно проектора живёт на хэше `#display`), а вреда от него
  много: отсутствующий `/app/data/*.json` приходил как `200 + HTML` и
  отравлял кэш данных, протухший JS-чанк отдавал HTML вместо скрипта.

## Структура

```text
site/                  # Статический лендинг (публикуется на корневом URL)
├── index.html
├── 404.html           # Страница ошибки для not_found_handling
├── og-image.png       # Превью для соцсетей
└── robots.txt, sitemap.xml, llms.txt
scripts/
├── smoke-serve.mjs    # Дымовой тест раздачи (npm run smoke)
└── og-image.svg       # Исходник превью
v3/                    # Единственная активная кодовая база приложения
├── data/source/       # Исходные базы переводов и песен
├── scripts/           # Конвертация и валидация данных
├── src/
│   ├── lib/components/
│   ├── lib/legacy/    # Минимальное временно переиспользуемое ядро поиска
│   ├── lib/*.svelte.ts
│   ├── App.svelte
│   └── main.ts
└── tests/

docs/                  # Архивные планы и аудит с отметками статуса
```
